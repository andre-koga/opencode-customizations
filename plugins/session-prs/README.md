# Orchestrator

**Orchestrator** is pinned in the session side pane's tab strip across chats. It is the fallback when a chat has no selected side-panel tab. Open the side pane and select **Orchestrator**, or run **Open Orchestrator** from the command palette. Other panels can still be selected, and the side pane can be hidden. The internal plugin ID remains `session-prs` so existing panel state is preserved.

The panel shows only chat tabs open in the current desktop window. It combines PRs for the current and previously visited local worktrees' branches with canonical GitHub PR links in that chat's messages, so a chat that moved between worktrees can show multiple PRs. A link indicates a PR was mentioned, not necessarily created or owned by that chat. PRs in a chat are deduplicated and each gets its own row with number, repository, title, colored state, checks and bot review findings. Findings come from the latest `github-actions[bot]` `review-done` marker in the most recent page of issue comments; `old` means its SHA differs from the current head and `—` means no marker was available. Findings are not necessarily the number of unresolved GitHub review threads. A single inaccessible PR does not hide the rest. Sessions without a PR remain visible; shared branches (`main`, `master`, `dev`, `develop`) are not matched to PRs. Click a chat name or branch to switch to that chat. Click a PR to open the native PR viewer when available, otherwise OpenCode's browser.

The window keeps its last displayed rows and session-history results in memory while switching panels. Reopening a recently checked panel reuses them without re-reading sessions; while visible, local session state is checked at most every 10 seconds, or when the open chats change. GitHub REST reads occur on the first load, when sessions appear or change directories, when a chat finishes, or when Refresh is pressed. Shared caches limit branch and individual PR lookups to once per minute. There is no continuous GitHub polling; CI changes that occur later require Refresh. To bound the work, history discovery reads up to 1,000 newest messages, 20 past locations and 100 referenced PRs; the row notes when the limit is reached. It ignores tool output except successful `gh pr create` results, avoiding unrelated PRs from listings. The GitHub CLI must be authenticated. Branch lookups require a local accessible directory; linked PR URLs can also be read for remote sessions.

To rebuild: `npm install` followed by `npm run build`. Run tests with `npm test`. This uses OpenCode's experimental desktop plugin API and may need updates for future versions.
